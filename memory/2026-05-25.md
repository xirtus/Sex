# 2026-05-25 — SexOS QEMU Debug Session

**Context:** Building and running SexOS microkernel on M1 MacBook Air via QEMU TCG x86_64 emulation.

## Session Goal
Boot SexOS in QEMU and fix visual bugs.

## Accomplishments

### Build pipeline fixes (macOS compatibility)
- Fixed `scripts/entrypoint_build.sh` and `scripts/sexos_build_trace.sh` to use `[[:space:]]` instead of `\s` in sed patterns (BSD sed on macOS doesn't support `\s`)
- Fixed `sexos_build_spec.toml` target path from absolute Arch path to relative `x86_64-sex.json`
- Reinstalled Homebrew `libgit2` to fix llhttp library mismatch

### Clock freeze (ss=18)
- Root cause: Handoff rejection between fallback and silkbar clock sources caused idle counter reset, freezing the clock on slow TCG emulation
- Fix: Replaced PIT-relative tick counting with per-display-loop clock advancement (`bar.clock_ss += 1` every loop iteration)
- Fast on native (silkbar takes over ms later), reasonable on TCG (~1 tick/sec)

### Glitch strip across silkbar
- Root cause: `bar_color` had a full-width early return at y=19..22 when `selected_options_mask != 0`, returning raw `DEFAULT_THEME.panel_fill` instead of the glass-composited background
- First fix attempt: Changed return to `glass_over_bg(panel_fill, ...)` — was incorrect because it still overrode workspace/chip/launcher module draws at those rows
- Second fix: Changed to only intercept the exact 3×3 dot pixel positions (36 out of 3840 pixels in the row range), falling through to normal module rendering for everything else

### Black flash on clock tick
- Root cause: `redraw_top_strip` cleared rows 0..49 with `bg(y, h)` (desktop gradient) before rendering the bar, which was briefly visible to the host display
- Fix: Removed the gradient clear entirely — the bar loop unconditionally covers all pixels

### Window control buttons too small
- Root cause: Surfaces start in minimal mode (`chrome_flags = 0`) before OP_SURFACE_TAB_INFO arrives. Minimal mode uses `FRAME_LIGHT_SIZE_PX = 4` and `FRAME_RIM_PX = 4`, making buttons 4×4 pixels (unclickably tiny)
- Fix: Increased `FRAME_LIGHT_SIZE_PX` to 8, `FRAME_RIM_PX` to 8, `FRAME_LIGHT_GAP_PX` to 3

### Close button appearing black/grey
- Root cause: `FRAME_LIGHT_CLOSE_DISABLED_BASE_ALPHA = 48` (19% opacity) made the red close light appear grey/black on dark background
- Fix: Increased to 160 (63% opacity)

### Post-drain surface redraw not firing
- Root cause: `redraw_surface_area` was gated by `!did_primary_fb_render`, but `did_primary_fb_render` was set to true on the same cycle by OP_PRIMARY_FB handler, preventing chrome flag updates from taking effect
- Fix: Removed the `!did_primary_fb_render` gate; `redraw_surface_area` now runs whenever `needs_surface_redraw` is true
