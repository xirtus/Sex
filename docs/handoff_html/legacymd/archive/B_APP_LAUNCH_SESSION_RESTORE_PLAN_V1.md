# B_APP_LAUNCH_SESSION_RESTORE_PLAN_V1

**Status:** Plan only. No implementation.

**Core principle:** Capability-native app launch and session restore for Silk DE. Launch and restore are shell-owned policies built on Track A (compositor lifecycle). No POSIX assumptions. No Linux .desktop compatibility. Every launch and restore is a proof-verified capability-native operation.

## 4. Object Model

- **AppIdentity:** capability-native app identifier. Not a filename or path. Survives path/name changes if trust identity is unchanged. Defined by publisher signature + capability root.
- **LaunchManifest:** describes authority, surfaces, expected services, and restore hints for one app. Fields: identity, version, required capabilities, surface constraints, restore hints, entry point PD reference.
- **LaunchIntent:** a recorded request to launch an app with specific capability/doc refs. Generated by user action (launcher click, document open, restore journal).
- **RuntimeInstance:** shell-side tracking for a launched app. Contains AppIdentity, SurfaceId(s), frame membership, launch timestamp, restart count, capability grant refs.
- **SurfaceRestoreRef:** reference to a surface identity from the journal. Validated against Track A lifecycle before restore. Historical/debug reference only unless validated.
- **DocumentRestoreRef:** Linen document reference. Not raw path authority. Resolved through Linen OpenIntent validation.
- **SceneRestoreJournal:** ordered journal of active Scenes, frames, tabs, surfaces, and their app identities at session end. One journal per session.
- **RestoreEntry:** one entry in the journal — app identity + CapabilityGrantSnapshot + SurfaceRestoreRef + DocumentRestoreRef + frame/tab placement + timestamp.
- **CapabilityGrantSnapshot:** the set of Collar grants an app held at journal time, stored as capability refs not raw tokens. Evidence, not authority.
- **RestartPolicy:** rules governing when and how to relaunch a crashed or missing app. Covers restart count limits, backoff, user intent preservation.
- **LaunchProofEvent:** proof marker payload for launch lifecycle transitions (request, capability check, spawn, surface create, failure).
- **RestoreProofEvent:** proof marker payload for restore lifecycle transitions (journal load, entry validate, capability revalidate, surface request, failure).

## 5. Launch Lifecycle

7 states + 3 terminal/error states:

```
  LaunchRequested ──→ CapabilityCheck ──→ ManifestValidated ──→ PDSpawned ──→ SurfaceCreated ──→ Running
       │                    │                     │                   │
       ▼                    ▼                     ▼                   ▼
  Rejected             Rejected              Rejected            SpawnFailed
  (user/               (capability           (manifest            (PD spawn
   policy)              denied)               invalid)             error)
```

- **LaunchRequested:** User action or LaunchIntent received. Guards: identity exists, not crash-looping, not already running. → CapabilityCheck or Rejected.
- **CapabilityCheck:** Collar verifies grants. If grants sufficient and not revoked → ManifestValidated. If insufficient → Rejected.
- **ManifestValidated:** Manifest parsed, fields validated. Entry point PD reference resolved. → PDSpawned or Rejected.
- **PDSpawned:** PD created, initial capability grants delivered. → SurfaceCreated (via Track A) or SpawnFailed.
- **SurfaceCreated:** Shell allocates surface through Track A lifecycle (Allocated→Mapped→Visible). → Running or SurfaceRejected.
- **Running:** App is live with surfaces, capability grants active, focus possible.
- **Rejected:** Terminal launch failure. User-visible via Bell event. Proof marker emitted with reason.
- **SpawnFailed:** PD creation error. Retry or abort per policy.
- **SurfaceRejected:** Surface creation failed via Track A. App PD notified, cleanup.

## 6. Restore Lifecycle

6 states + 3 terminal/error states:

```
  JournalFound ──→ EntryValidated ──→ CapabilityRevalidated ──→ SurfaceRequested ──→ DocumentResolved ──→ Running
       │                │                       │                       │
       ▼                ▼                       ▼                       ▼
  Empty            EntryRejected          CapRevoked              SurfaceFailed
  (no journal)     (stale/missing)
```

- **JournalFound:** SceneRestoreJournal loaded from memory (E gate not yet required; V1 memory-only). → EntryValidated per entry or Empty.
- **EntryValidated:** RestoreEntry parsed, fields valid, SurfaceRestoreRef not referencing destroyed ID. → CapabilityRevalidated or EntryRejected.
- **CapabilityRevalidated:** Collar re-verifies grants from CapabilityGrantSnapshot. If grants still valid → SurfaceRequested. If revoked → CapRevoked.
- **SurfaceRequested:** Shell requests new live surface through Track A lifecycle (Allocated→Mapped→Visible). → DocumentResolved or SurfaceFailed.
- **DocumentResolved:** DocumentRestoreRef validated through Linen OpenIntent. If valid → Running. If missing → safe placeholder.
- **Running:** App restored. Same semantics as launch Running state.
- **Empty:** No journal → clean boot. No restore needed.
- **EntryRejected:** Journal entry stale, app missing, identity changed. Produces tombstone/event. Restore continues with remaining entries.
- **CapRevoked:** Capability revoked since journal. Entry skipped, user notified via Bell/Mesh.
- **SurfaceFailed:** Surface creation failed. Retry bounded per RestartPolicy.

## 7. Allowed Transitions

| From | To | Trigger | Guard | Proof Marker | Failure |
|------|----|---------|-------|-------------|---------|
| LaunchRequested | CapabilityCheck | User/Intent trigger | Identity exists, not already running, not crash-looping | `[launch.request]` | Loop limit → `[launch.reject]` reason=crash_loop |
| CapabilityCheck | ManifestValidated | Collar grants sufficient | All required capabilities present and unrevoked | `[launch.capability.ok]` | Insufficient → `[launch.capability.reject]` |
| ManifestValidated | PDSpawned | Entry point resolved | Manifest fields valid, PD reference exists | `[launch.manifest.ok]` | Invalid → `[launch.manifest.reject]` |
| PDSpawned | SurfaceCreated | PD created | PD handle acquired, capabilities delivered | `[launch.pd.ok]` | Spawn error → `[launch.pd.fail]` |
| SurfaceCreated | Running | Surface visible | Track A lifecycle: Allocated→Mapped→Visible | `[launch.surface.ok]` | Surface rejected → `[launch.surface.reject]` |
| JournalFound | EntryValidated | Journal parsed | Format valid, no corruption | `[restore.journal.load]` | Corrupt → `[restore.journal.reject]` |
| EntryValidated | CapabilityRevalidated | SurfaceRestoreRef checked | ID not destroyed, identity not stale | `[restore.entry.validate]` | Stale → `[restore.entry.reject]` reason=stale |
| CapabilityRevalidated | SurfaceRequested | Collar re-validates | CapabilityGrantSnapshot still valid | `[restore.capability.ok]` | Revoked → `[restore.capability.reject]` |
| SurfaceRequested | DocumentResolved | Surface created | Track A lifecycle produces live surface | `[restore.surface.ok]` | Failed → `[restore.surface.reject]` |
| DocumentResolved | Running | Doc validated | Linen OpenIntent approves | `[restore.document.ok]` | Missing → `[restore.document.placeholder]` |

## 8. Forbidden Transitions

| From | To | Why |
|------|----|-----|
| Any launch state | Running | Must pass through all lifecycle states in order |
| Running (launch) | Rejected | Cannot reject a Running app — must use Track A lifecycle (Closing→Tombstoned→Destroyed) |
| Rejected/SpawnFailed/SurfaceRejected | Running | Terminal — cannot resurrect failed launch |
| EntryRejected/CapRevoked/SurfaceFailed | Running | Terminal — cannot resurrect failed restore entry |
| Any (during crash/restart loop) | Running | Loop limit must trigger Bell event, not silent retry |
| JournalFound | Running (skip validation) | Every entry must validate; no bulk-restore bypass |
| CapabilityCheck | PDSpawned | Must go through ManifestValidated first |
| ManifestValidated | CapabilityCheck | Already passed capability check |
| SurfaceRequested | CapabilityRevalidated | Already passed capability revalidation |

## 9. Capability / Collar / Package-Trust Boundary

- Launch requires capability verification before PD spawn. Shell requests capability check from Collar; Collar responds allow/reject.
- Package trust waits G gate. V1: trust verification is design-only, not implemented. Manifest presence does not imply trust.
- CapabilityGrantSnapshot in restore journal is evidence of past grants, not authority. On restore, Collar re-verifies from current trust state.
- App identity is capability-native: publisher signature + capability root define identity. Path and filename changes do not change identity.
- Revoked capabilities at restore time produce CapRevoked state, not silent grant.
- Crash cannot mark an app trusted. Restart count resets only after successful user interaction.
- Launch manifest declares required capabilities. Manifest cannot declare capabilities the package could not legitimately request (policy validation).
- Collar auto-grant / prompt-once strategies are Collar policy, not launch/restore policy. Launch/restore only verifies.

## 10. Scene/A Lifecycle Dependency

- B (App Launch/Session Restore) depends on A (Compositor Lifecycle) A1-A4 before any implementation:
  - A1: Audit current lifecycle — understands what exists
  - A2: FSM spec — defines the surface lifecycle states
  - A3: Shell lifecycle model — state tracking, LifecycleGeneration, FocusRef
  - A4: Focus validity guards — try_set_focus, clear_focus_if_dead
- Surface creation at launch: shell requests Allocated→Mapped→Visible through Track A transitions
- Surface restore: shell requests new live surface through Track A; never resurrects destroyed SurfaceIds
- Running apps remain in Track A lifecycle (Visible, Hidden, Minimized, Closing, Tombstoned, Destroyed)
- Focus for launched/restored apps: Track A focus validity rules apply. apps cannot force focus.

## 11. Storage/E and Linen/F Dependency

- Durable SceneRestoreJournal persistence waits E gates (E5-E9). V1: memory-only journal.
- DocumentRestoreRef validation depends on Linen OpenIntent validation (Track F).
- CapabilityGrantSnapshot references Collar data model; Collar capability storage depends on E track.
- Package trust / verification waits G gate. V1: manifest format exists but trust is design-only.
- E dependency order: E5 (KV API), E9 (persistence stabilization) for restore journal survival.
- F dependency: DocumentRestoreRef validation depends on Linen/F OpenIntent canon and E storage gates. B must not treat DocumentRestoreRef as raw path authority.

## 12. Sexdisplay Conformance Rules

1. sexdisplay renders shell-provided visual state only. Never decides launch policy, restore policy, or app identity.
2. sexdisplay receives surface create/destroy/update/focus opcodes from shell. No launch-specific opcodes.
3. sexdisplay never restores surfaces — shell creates all surfaces through Track A lifecycle.
4. sexdisplay never rejects surfaces based on app identity — it renders what the shell provides.
5. No oob/geometry-based surface state. All surface geometry bounds-checked before sexdisplay receives it.

## 13. Invariants

1. Restore never grants new authority — only re-validates previously granted capabilities.
2. Restore never resurrects destroyed SurfaceIds — requests new live surfaces through Track A.
3. SurfaceRestoreRef is historical/debug reference only unless validated against Track A lifecycle.
4. DocumentRestoreRef is not raw path authority — resolved through Linen OpenIntent.
5. App association (surface↔manifest) is a hint, not permission. Shell validates membership.
6. CapabilityGrantSnapshot is evidence of past grants, not authority. On restore, Collar re-verifies.
7. Crashed app cannot mark itself trusted. Restart count resets only after successful user interaction.
8. Package trust waits G gate — trust verification is design-only in V1.
9. Durable restore (journal persistence) waits E gate — V1 memory-only.
10. Document restore waits Linen/OpenIntent validation — DocumentRestoreRef unresolved before F.
11. Partial restore must be safe and explainable — missing entries produce events, not crashes.
12. Restart loops are bounded — count + backoff before Bell alert.
13. sexdisplay only renders shell-provided model — no launch/restore/identity awareness.
14. Apps cannot force focus — Track A focus validity rules apply.
15. Unknown or stale restore entries reject deterministically — no silent acceptance.
16. Launch produces a unique RuntimeInstance per launch — no duplicate RuntimeInstances.
17. Identity change between journal and restore produces EntryRejected — trust must be re-established.
18. All launch and restore state transitions produce proof markers — no silent state changes.
19. SceneRestoreJournal is shell-owned — sexdisplay, Linen, and apps cannot write to it.
20. Launch manifest fields beyond known schema are ignored or rejected deterministically — no extension injection.
21. Failed restore never leaves partially-initialized RuntimeInstance — cleanup to Tombstoned/Removed.

## 14. STOP FIRST Gates

- Any sexdisplay or Linen owning launch/restore policy
- Any destroyed SurfaceId resurrection during restore
- Any kernel/ABI/sex-pdx edit without explicit handoff
- Any POSIX process/session model assumption (PID, env, CWD, fd, argv)
- Any Linux .desktop compatibility as launch manifest foundation
- Any raw path-based trust for app identity or document location
- Any restore of raw pointers or cross-PD memory references
- Any implementation before A1-A4 are complete
- Any package trust implementation before G gate
- Any durable storage implementation before E gates
- Any Linen document validation before F gate
- Any unbounded restart loop without count/backoff
- Any trusting of crashed app-provided state without validation
- Any bulk-restore bypass of per-entry validation

## 19. Scan 8 — Customization / User Policy Surface

Customization is shell-owned, validated, reversible, accessible, and unable to customize away launch/restore safety.

### Customizable (10 domains)

| Preference | Options | Constraint |
|-----------|---------|------------|
| Default launch scene/frame | scene_idx, frame_position | Lifecycle-validated before apply |
| Restore prompt strictness | restore_all, prompt_per_app, skip_all | Cannot bypass capability checks |
| Per-app restart preference | auto_restart, prompt, disabled (bounded) | Cannot create unbounded loop |
| Restore order preference | z_order, launch_time, manual | Deterministic across replay |
| Partial restore behavior | skip_placeholder, prompt, show_tombstone | Missing entries never become live |
| Crash restore visibility | silent_placeholder, bell_event | Cannot suppress required Bell events |
| App association preference | hint, none | Hint only; shell validates membership |
| Recent app/session visibility | show_all, show_active_only, hide | Privacy-gated; redacted per E8 |
| Proof verbosity | minimum, normal, debug | Cannot suppress required launch/restore markers |
| Keybindings (future) | scancode+modifiers | After D accessibility + shortcut audit |

### Not Customizable (12 hard boundaries)

Capability checks; Collar grants; package trust; destroyed SurfaceId resurrection; Track A lifecycle validation; OpenIntent validation; storage/E gates; Linen/F document validation; PDX ABI/opcodes; required proof markers (safety markers always fire); sexdisplay ownership boundary; app ability to force focus/trust.

### Customization Proof Scenarios

1. Valid launch scene preference accepted after lifecycle validation → `[launch.pref.accept]` scene=N.
2. Invalid scene/frame target rejected or reset to default → `[launch.pref.reject]` reason=invalid_scene.
3. Restore prompt strictness=skip_all still validates capabilities → `[restore.capability.reject]` if revoked. Strictness affects UI only.
4. Per-app restart preference=auto_restart bounded by max count/backoff → `[launch.crash_loop]` fires at limit regardless of preference.
5. App association preference=hint does not bypass shell membership validation → `[launch.surface.reject]` if invalid frame.
6. Recent session visibility=hide redacts entries but journal still validates → `[restore.entry.validate]` fires regardless of visibility setting.
7. Proof verbosity=minimum still emits `[launch.request]`, `[launch.reject]`, `[restore.entry.validate]`, `[restore.capability.reject]` — required safety markers never suppressed.
8. Restore order=manual still validates all entries before ordering → `[restore.entry.reject]` for stale entries before order applied.
9. Keybinding before audit rejected → `[launch.pref.reject]` reason=no_audit. Planned-only until D accessibility gate.
10. Reset-to-safe-default restores canonical behavior → `[launch.pref.reset]`. All preferences back to compiled defaults.

### Preference Lifecycle

1. **Load** → `[launch.pref.load]`. 2. **Validate** → `[launch.pref.validate.ok]` or `.reject`. 3. **Apply** → `[launch.pref.apply]` (UI prefs immediate; policy prefs need guard re-validation). 4. **Persist** → blocked until E gates pass (memory-only in V1). 5. **Redact** → `[launch.pref.redact]` per E8 policy. 6. **Reset** → `[launch.pref.reset]`.

## 21. Final Safest Path

1. **B1 audit first** — Current shell launch capabilities must be audited before any design. Skipping B1 means design targets are based on assumptions, not reality.
2. **Identity/manifest before runtime model** — B2 (identity + manifest) must precede B3 (LaunchIntent) and B4 (RuntimeInstance) because the manifest defines the identity model.
3. **Launch model before restore** — B3-B4 (launch) must precede B5-B6 (restore) because restore re-uses launch's identity, capability, and surface creation paths.
4. **Validation before journal** — B6 (validation proofs) must define the gates that B5 (journal) must satisfy. Journal format without validation gates is brittle.
5. **Integration gate last** — B7 verifies every launch/restore transition produces correct proof markers and every forbidden transition is blocked. Must come after all preceding phases.
6. **No implementation before A1-A4** — STOP FIRST for any launch/restore code changes before Track A compositor lifecycle is audited (A1), specified (A2), modeled (A3), and focus-guarded (A4).
7. **No durable restore before E gates** — SceneRestoreJournal is memory-only until E5-E9 provide storage maturity.
